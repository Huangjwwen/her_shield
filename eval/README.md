# 言行雷达判定准确率评测

这一目录是给「她眼·言行雷达」核心判定流程的**内部对齐基准**——用一组手工精标的、锚定到真实判例的测试用例,验证产品在常见职场性别歧视/性骚扰场景下,是否能给出与法律共识一致的风险等级与判定理由。

> **声明**:这不是宣称"AI 达到法官水平"的外部评测,是开发期产品对齐用的内部基准。生产环境会持续扩充并由外部专家复核。

---

## 一、文件清单

| 文件 | 用途 |
|------|------|
| `test_set.json` | 标注测试集(版本 v1.3,共 **100 条 = 50 精标 + 50 变体**) |
| `run.js` | 评测脚本(Node 18+,支持代理 / 直连元器,含节流和重试) |
| `results-v1.3*.json`(运行后生成) | 评测结果详情,含混淆矩阵、各等级召回、变体鲁棒性 |
| `README.md` | 本文件,讲方法学和运行步骤 |

## 二、风险等级判定规则(评测基准)

四级输出,由代码节点确定性映射(详见 `js/radar.js` 的规则映射文档及"要件式判定 + 风险分级"System Prompt):

| 等级 | 触发条件 |
|------|---------|
| 🔴 高危 | 骚扰:三要件全满足 **且** 至少一项加重情节;或 H1+H2 满足 **且** 加重含肢体/职权胁迫。歧视:D1+D2 满足 **且** 制度性 或 已造成实质后果 |
| 🟠 中危 | 关键要件满足、另有要件满足**或存疑**,未达高危 |
| 🟡 低危 | 关键要件满足但其余多缺失,或关键要件**存疑**(召回优先) |
| 🟢 无风险 | 关键要件均不满足 |

## 三、测试集如何构造(应对"凭什么这么标")

### 3.1 五道防线
1. **每条标注挂真实判例或法条**:`anchor` 字段写明参照的法院/案号/年份/检察机关典型/法条编号,评委可追溯。
2. **测试集公开**:`test_set.json` 在仓库内,所有标注理由透明。
3. **分层评测**:不只报"整体准确率",还报各等级召回、各分类准确率、混淆矩阵。
4. **主动声明边界**:声明这是开发期内部基准,不是法官级评测。
5. **方法学透明**:本文件第三节即是。

### 3.2 案例覆盖与来源
- **总用例数**:**100 条 = 50 精标 + 50 变体**
- **精标分类分布**(50 条):

| 子类 | 用例数 |
|------|--------|
| 骚扰-高危 | 8 |
| 骚扰-中危 | 8 |
| 骚扰-低危 | 5 |
| 歧视-高危 | 8 |
| 歧视-中危 | 8 |
| 歧视-低危 | 5 |
| 无关-无风险 | 8 |

- **变体分类分布**(50 条,测语言/细节/干扰/边界/长文本鲁棒性):

| 变形类型 | 用例数 | 用途 |
|---------|-------|------|
| 同义改写 (paraphrase) | 15 | 测语言鲁棒性,不改 risk_level |
| 细节扰动 (perturb) | 12 | 测是否过拟合表面词,不改 risk_level |
| 干扰句 (distract) | 10 | 测聚焦能力(加无关句子),不改 risk_level |
| 要件边界 (boundary) | 8 | 故意削弱/加强一个要件,**会改 risk_level** —— 测规则贴合度 |
| 长文本扩展 (verbose) | 5 | 把短描述拉长,测对自然长篇输入的稳定性 |

每条变体的 `variant_of` 字段指向原精标 id,`variant_type` 字段说明变形手法。

- **锚点类型分布**(50 精标的 `anchor.type` 字段):
  - `judicial`(真实司法判例 / 检察机关典型案例):17 条
  - `statute`(法律条文明文禁止):6 条
  - `derived`(由判例规则推导,主要用于低危边界与无关项):27 条

### 3.3 真实判例锚点示例
- D_real_1:严女士 vs 某公司平等就业权纠纷案(上海浦东法院 2023)
- D_real_2:韩坤诉厦门翔鹭化纤股份有限公司劳动争议案 (2009)厦民终字第2188号
- D_real_3:某电子公司 vs 林某劳动争议案(2023)
- H_real_1:周某强制猥亵案(芜湖镜湖区检察院 2023)
- H_real_2:陈某 vs 杨某等人格权纠纷案
- D8:谷歌同工不同酬集体诉讼(2021-2022 美国加州,1.18 亿美元和解,国际锚点 + 国内法条)
- D2/D4 等:赵某孕期降薪案(最高法第四批劳动争议典型案例 2025)、马某 vs 某公司案(2021)

### 3.4 标注一致性
- 每条都按"四级准则"判定,标注理由写在 `notes` 字段;
- 模糊或边界情形默认"召回优先"——存疑往上判,不往下判;
- "无关"项(N1-N5)用于测产品的拒答能力,防止把所有问题都套用判定。

## 四、怎么跑评测

### 4.1 前置:Node.js 18+
脚本用了内置 fetch,需要 Node 18 或更高。`node --version` 检查。

### 4.2 默认模式:走线上代理
```bash
cd her_shield
node eval/run.js
```
> ⚠️ 当前(2026-05-30)线上代理云函数返回 `未知 agentType`,**所有调用会失败,所有等级判错**。第1组修复代理后此模式立即生效。

### 4.3 备用模式:直连元器(代理挂了时用)
```bash
KEY_RADAR='你的 radar appkey' node eval/run.js --direct
```
或:
```bash
node eval/run.js --direct --key 你的 radar appkey
```
直连绕开代理,直接打元器 API。需要 radar 智能体的 appkey(在元器后台查)。

### 4.4 其他选项
```bash
node eval/run.js --limit 5          # 只跑前 5 条快测
node eval/run.js --concurrency 1    # 并发 1(直连元器避免限流)
node eval/run.js --delay 2000       # 每条请求间隔 2 秒(节流;--direct 模式默认 1500ms)
node eval/run.js --retry 3          # 失败重试 3 次,指数退避(--direct 模式默认 2)
node eval/run.js --output eval/r1.json  # 自定义结果文件
node eval/run.js --help             # 看完整帮助
```

> 💡 **元器直连容易触发服务端限流**(连续打同一 appkey 返回 HTTP 500)。`--direct` 模式自动开启 1.5 秒节流 + 2 次重试。100 条评测预计 10-20 分钟跑完。代理模式无此问题(走 CloudBase 缓存)。

### 4.5 输出
- 控制台:实时进度 + 汇总(整体准确率 / 各等级召回 / 各分类准确率 / 混淆矩阵 / 失败样本)
- 文件 `eval/results.json`:全量明细 + 汇总数据,可二次绘图

## 五、答辩用法(给 PPT 喂数据)

跑完一次后,`results.json` 提供这些可直接进 PPT 的指标:

| 指标 | 字段 | 用法 |
|------|------|------|
| 整体准确率 | `overall_accuracy` | "在 36 条真实判例锚定的测试集上,准确率 XX%" |
| 高危召回率 | `recall_per_level.高危` | "对真实需要紧急介入的高危场景,识别召回率 XX%" |
| 混淆矩阵 | `confusion_matrix` | 画一张 4×4 热力图,直观展示模型在哪类边界容易混淆 |
| 各分类细分 | `by_category` | 拆开看产品在每个子类的稳定性 |

### 5.1 95% 置信区间(供严谨答辩)
当 **n=100** 且 p≈85%,95% CI ≈ ±7%。报"准确率 XX%,95% 置信区间 XX% – XX%",体现统计素养。
对比 v1.2(n=36)的 ±11.7%,扩到 100 条后误差范围窄了将近一半。

### 5.2 答辩话术
> "我们的测试集共 **100 条 = 50 条精标 + 50 条变体**。50 条精标中,**17 条直接锚定到具体司法判例**(含案号/法院/年份),**6 条锚定到法律条文明文禁止**的行为,**27 条由判例规则派生**(主要用于无关项与低危边界)。50 条变体覆盖**同义改写 / 细节扰动 / 干扰句 / 要件边界 / 长文本扩展**五类,专门测产品在语言变化下的鲁棒性。所有标注理由公开在 `test_set.json` 的 `notes` 和 `anchor` 字段中,欢迎逐条核查。"
