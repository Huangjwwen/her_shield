# 标注指南 — 要件级人工标注

> 目的:把每条用例的 `risk_level` 从"标注者心算"升级为"要件事实标注 + 代码机械映射"。
> 标完之后,跑 `node eval/validate-annotation.js` 自动用 `compute_risk_level` 校验,
> 输出"代码算出来的等级"vs"当前 expected"的差异,差异的就改 expected。

## 填写规范

### 1. 涉性骚扰类(category 含"骚扰" 或 variant 指向骚扰精标)

- **必填**:h1 / h2 / h3
- **加重情节(agg_*)**:逐项填 Y 或 N。**留空 = 没判断**,不等于 N。
- e1/e2 / discrim_*:**填"不适用"**(除非该用例同时涉歧视,比如 H10 婚育询问)

### 2. 涉性别歧视类(category 含"歧视" 或 variant 指向歧视精标)

- **必填**:e1 / e2 / discrim_institutional / discrim_concrete_harm
- h1/h2/h3 / agg_*:**填"不适用"**(除非该用例同时涉骚扰)

### 3. 无关类(N1-N8 / V_pp_13-14 / V_pt_11-12 / V_dt_08-09 / V_bd_06)

- 所有要件字段全部"不适用"
- final_level 必为"无风险"

### 4. 同时涉两类(如 H10 "你长得不错怎么没结婚")

- 骚扰 + 歧视 双线都填
- type 标 "性骚扰+性别歧视"

### 5. 边界变体(V_bd_*)

- 这类的 expected 跟原精标可能不同 —— 看 notes 写的边界变化方向
- **如:V_bd_05** 是"H6 中危加入显式职权胁迫 → 升为高危"
  - h2 从存疑 → 满足
  - agg_职权胁迫: Y(原 H6 是 N)
  - final_level 应升为高危

## 取值定义(关键)

### "满足" vs "存疑" vs "不满足"

| 标 | 判断标准 |
|---|---|
| **满足** | 描述明确呈现该要件,无合理另解 |
| **存疑** | 描述里有蛛丝马迹,但**关键事实没说**(如"违背意愿"——受害者没明确拒绝也没明确同意) |
| **不满足** | 描述明确排除该要件(如"我们关系很好,他这么说是开玩笑") |
| **不适用** | 该要件跟此类无关(如歧视案例填骚扰要件) |

**规则:模糊时归"存疑",不归"满足"** —— 召回优先体现在代码的 compute_risk_level,不要在事实判断里"为了高分自动满足"。

### "institutional" vs "concrete_harm"

- **institutional = 是**:写进劳动合同/规章/招聘启事/内部规定/书面流程,**未必造成实际后果但已具备制度性歧视形式**。例:"招聘启事写仅限男性""女员工入职须签三年不生育"
- **concrete_harm = 是**:已经造成实际后果。例:"撤回 offer""孕期辞退""降薪 40%""失去晋升机会"

两者**可同时为是**(写进合同 + 已经执行),**也可只一项为是**(只写没执行 / 没写但已执行)。

## 标完后的校验流程

1. 把填完的 CSV 提交到 `eval/annotation_filled.csv`
2. 跑 `node eval/validate-annotation.js` (待我下一步生成)
   - 脚本会把每条要件状态丢给 `compute_risk_level` 算出 risk_level
   - 跟 `current_expected_level` 对比,差异行列在 console
3. 差异行:
   - 如果标注者认为代码算的对 → 修改 test_set.json 的 expected.risk_level
   - 如果代码算的不对 → 说明 compute_risk_level 规则有 bug,改代码
4. 最终 test_set.json 和 compute_risk_level 必须 100% 对齐 —— 这才能在答辩时说"标准答案和产品输出走同一份映射代码,差异只来自 AI 对事实的判断"

## 工时估算

- **50 条精标**:每条 3-5 分钟 → 2.5-4 小时
- **50 条变体**:大部分继承精标(只填 final_level 或备注"同 H1"),边界变体 8 条单独 → 1-1.5 小时
- **校验脚本跑 + 调差异**:1 小时
- **合计**:**半天到一天**(单人;两人分摊更快)

## 出错样例(避免犯)

### ❌ 错误标法
- "他说我长得不错怎么还没结婚"
  - h1: 满足  (✗ 应该是"满足"还是"存疑"?)
  - 答:"长得不错"是性化评价 → h1 满足;"怎么还没结婚"是婚育询问 → 不构成 h1,但触发 e1(区别对待)+ e2(招聘)
  - 正确:h1=满足, h2=存疑(未明确拒绝), h3=满足(面试场合), e1=满足, e2=满足

### ❌ 错误标法
- "公司招聘启事写仅限男性"
  - h1: 不满足 (✓ 这点对)
  - institutional: 否 (✗ 错!写进招聘启事就是 institutional=是)
  - concrete_harm: 否 (✓ 这是"形式歧视",还没人因此被实际排除)
  - 正确:e1=满足, e2=满足, institutional=是, concrete_harm=否 → 代码会给高危
