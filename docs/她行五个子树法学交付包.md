# 她行五个子树法学交付包

> 适用场景：`pregnancy_pay_cut`、`recruit_discrimination`、`harassment`、`equal_pay_promotion`、`leave_benefits`  
> 文档性质：法学初稿，供开发转换和第二法学审核使用  
> 建议版本：树规则 `1.3.0-draft`，条件索引 `1.3.0-draft`，模板 `1.2.0-draft`  
> 核验日期：2026-08-02

## 1. 交付范围与边界

本交付包完成以下法学任务：

1. 五棵子树的节点、选项技术值、下一跳、标记和终点条件；
2. 每个终点的行动重点、文书白名单和不应输出的结论；
3. 五棵树使用的文书模板元数据、自然语言正文和字段来源；
4. 会出现在裁决包法律依据区的国家法条原文；
5. 终点法律依据映射和条件规则；
6. 法学审核用例与发布前检查表。

本交付包不处理单纯违法解除、逼迫离职或与女性职场性别歧视无关的普通劳动争议。用户提到解除或离职时，只判断其是否与性别、婚育、孕产或投诉维权存在关联；明确无关的，进入 `OOS`。

以下内容不得由系统直接断言：

- 只要工资不同就构成同工不同酬；
- 只要没有晋升就构成性别歧视；
- 所有地区的延长产假、奖励假、哺乳假和生育津贴规则相同；
- 超过一年一定不能仲裁；
- 生育津贴低于个人工资时，在所有地区均由单位补足；
- 用户一定胜诉、单位一定违法或某项请求一定会获支持。

## 2. 孕期、产期、哺乳期调岗降薪子树

### 2.1 场景目标与边界

本树处理与怀孕、生育、产假或哺乳存在关联的调岗、降薪、扣减绩效、降低待遇、增加不适宜劳动、要求离职和解除风险。单纯违法解除、一般岗位调整或与孕产及性别无关的离职纠纷不在服务范围内。

用户无法判断关联时不得过早拦截。除非用户明确确认解除原因与孕产、性别、婚育无关，且通知、时间顺序、单位表述等均不存在其他关联线索，否则一律按 `relation_uncertain` 继续收集事实，不得默认进入 `OOS`。界面应把“明确无关”解释为用户已经掌握并确认可核对的其他原因，而不是“目前没有证据证明有关”。

| `P2` | 你目前和单位的关系是？ | `employed` 仍在职 → `P3`；`left_due_to_pregnancy` 因孕产问题已离职 → `P4`；`oral_dismissal_related` 因孕产问题被口头辞退但未办离职 → `P4`；`termination_notice_related` 因孕产问题收到解除通知 → `P4`；`relation_uncertain` 不确定解除是否与孕产有关 → `P4`；`confirmed_unrelated` 明确确认无关 → `OOS` | `relation_uncertain` 写入 `{node:P2, flag:relation_uncertain}`；此时 `P4` 的提示须先说明“建议同步核对解除原因与时间关联” |

| `P6` | 公司已经实际采取了什么行为？ | `transfer_only` 仅调岗 → `P7`；`salary_reduced` 仅降薪/扣绩效 → `P7`；`both` 调岗并降薪 → `P7`；`exit_requested` 要求主动辞职 → `P8`；`terminated` 解除劳动合同 → `P8`；`relation_uncertain` 无法判断行为是否与孕产有关 → `P9` | 本节点只在措施已经发生时展示，前三项本身即表示已经实施；`relation_uncertain` 写入来源为 `P6` 的同名标记并先收集证据，不强迫用户回答签署问题；解除或逼迫离职路径继续收集证据，但最终只能进入服务边界终点 `PF` |

| `P8` | 是否签过离职、调岗、降薪或协商解除文件？ | `unsigned` 未签 → `P9`；`signed_under_pressure` 已签但不情愿 → `P9`；`voluntary_resignation_submitted` 主动提交过辞职 → `P9`；`document_uncertain` 不确定文件内容 → `P9` | 后三项生成同名来源标记；不得在此直接跳终点，所有路径继续收集证据 |
| `P9` | 你手上有哪些材料？（多选） | `chat_email` 聊天/邮件；`payroll` 工资流水；`pregnancy_record` 孕产证明；`contract_job_description` 合同/岗位说明；`attendance` 考勤；`none` 暂无 → 均进入 `P10` | `none` 与其他项互斥并标记 `evidence_weak` |

### 2.3 终点裁决规则

| 终点 | 权威触发条件 | 行动重点 | 后端文书 |
|---|---|---|---|
| `PA` 未正式行动 | `P10=none/oral_communication`，且没有 `P8` 的签署风险标记 | 书面提出异议，固定通知内容、孕产时间和反对意见 | `salary_objection`、`evidence_catalog`；`P6=transfer_only/salary_reduced/both` 时可按具体行为附 `restore_position_salary_request` |
| `PB` 已沟通/投诉或签署风险 | 已书面/外部投诉，或存在 `signed_under_pressure`、`document_uncertain`；`voluntary_resignation_submitted` 属于服务边界并进入 `PF` | 先核对文件和真实意思表示，再按具体请求准备监察或仲裁材料 | 默认 `evidence_catalog`；符合人社/劳动保障监察职责时附 `labor_inspection_materials`；存在可仲裁的具体劳动请求时附 `arbitration_application_points`；`P6=transfer_only/salary_reduced/both` 时可按具体行为附 `restore_position_salary_request` |
| `PC` 时效核验 | `P4=over_one_year` 且尚未进入仲裁 | 已完成事实与证据收集；核对时效起算、中断、中止、持续欠薪及当地程序，不直接宣告权利消灭 | `legal_aid_questions`、`evidence_catalog` |
| `PD` 已仲裁 | `P10=arbitration_started` | 对照仲裁请求补齐事实、金额、时间线、送达及关联证据 | `arbitration_supplement_list`、`evidence_catalog` |
| `PE` 尚无明确措施 | `P3A=vague/attitude_only`，或 `P4=not_started` 且不存在 `anticipated_exit` | 记录原话、时间、参与人、现岗位待遇和后续变化，不要求用户回答尚未发生的影响 | `evidence_catalog` |
| `PF` 孕产关联解除/离职边界 | 尚未仲裁，且 `P2=left_due_to_pregnancy/oral_dismissal_related/termination_notice_related/relation_uncertain`、`P6=exit_requested/terminated`、`P8=voluntary_resignation_submitted`，或存在 `{node:P3A, flag:anticipated_exit}` | 仅固定孕产关联、解除或离职文件、沟通时间线和送达情况；说明本项目不判断违法解除，也不生成解除、辞职、赔偿、时效或仲裁请求类文书 | 仅 `evidence_catalog`；不得返回 `legal_aid_questions`、`salary_objection`、解除通知回复、仲裁请求或赔偿计算文书 |
| `OOS` 范围外 | `P2=confirmed_unrelated` | 说明不处理与性别、婚育、孕产或性骚扰报复无关的普通解除争议 | 不返回文书 |

### 2.4 裁决与措辞约束

- 不得将“发生在孕期”直接等同于“因孕产而实施”；
- 不得因用户签字就断言其放弃全部权利，也不得断言签字当然无效；
- `relation_uncertain` 路径应提示补充不利措施与告知怀孕、产假开始或返岗时间的关联；`{node:P2, flag:relation_uncertain}` 表示解除关联不明，可触发 `PF`，`{node:P6, flag:relation_uncertain}` 表示行为关联不明，只用于补证和措辞，不得单独触发 `PF/PC`；
- `harm_low` 路径不得写“没有损害”或“公司可以调岗”；
- 涉及解除只处理其与孕产歧视的关联和材料准备，不扩展为通用违法解除服务。

### 2.5 条件标记

本树使用 `relation_uncertain`、`anticipated_action`、`anticipated_exit`、`time_uncertain`、`time_risk`、`harm_low`、`signed_under_pressure`、`voluntary_resignation_submitted`、`document_uncertain`、`evidence_weak`、`need_written_record` 和 `arbitration_started`。同名标记必须带来源节点消费；模板条件和终点规则不得只按标记字符串匹配，具体写法以主手册 10.5.7 为准。

## 3. 招聘/面试性别歧视子树

### 3.1 场景目标与边界

本树处理招聘广告限定男性或男性优先、询问或调查婚育、把妊娠测试或婚育状态作为录用条件，以及其他基于性别拒录或差别化提高标准的线索。系统帮助用户固定招聘原文、面试沟通和不利结果，并选择企业说明、平台投诉或行政反映路径；系统不替企业决定录用，也不因一次未录用直接认定构成歧视。

### 3.2 完整节点表

| 节点 | 问题 | 技术选项与下一跳 | 标记/法学说明 |
|---|---|---|---|
| `R1` | 歧视发生在哪个环节？ | `job_posting` 招聘广告/岗位要求 → `R2`；`interview` 面试提问 → `R2`；`offer_cancelled` 录用前后取消 offer → `R3`；`rejected_after_application` 投简历后被拒 → `R3` | 保留招聘页面、岗位名称、发布时间和主体信息 |
| `R2` | 是否明确提到性别、婚育、怀孕或生育计划？ | `explicit_reference` 明确提到 → `R4`；`implicit_or_questioning` 暗示或追问 → `R4`；`no_explicit_reference` 没有明确表述 → `R5` | 婚育询问本身是重要线索，但仍要记录上下文和后续结果 |
| `R3` | 是否已经出现不利结果？ | `no_interview` 未进入面试 → `R2`；`not_hired` 未被录用 → `R2`；`offer_cancelled_or_reduced` offer 被取消或待遇降低 → `R2`；`awaiting_result` 尚无结果 → `RA` | 所有拒录或取消 offer 路径必须继续核对性别、婚育关联，不能仅凭不利结果进入投诉 |
| `R4` | 你有哪些材料？（多选） | `job_posting_screenshot` 招聘广告截图；`chat_email` 聊天/邮件；`recording_interview_notes` 本人参与的录音/面试记录；`rejection_notice` 拒录通知；`none` 暂无 → 有材料进入 `R6`，`none` 进入 `RA` | `none` 与其他项互斥并标记 `evidence_weak`；不得建议窃听或非法获取他人信息 |
| `R5` | 是否有可比较信息或持续模式？ | `male_comparator` 同岗位男性被正常推进 → `R6`；`company_pattern` 公司长期限制女性 → `R6`；`no_comparator` 暂无对比信息 → `RA`；`confirmed_unrelated` 已明确核对为非性别、婚育原因 → `OOS` | 可比信息仅作为线索；`confirmed_unrelated` 必须由用户主动确认，不得由系统推断 |
| `R6` | 你希望先走哪种方式？ | `request_explanation` 要求企业说明 → `RB`；`platform_complaint` 向招聘平台投诉 → `RB`；`civil_consultation` 了解就业歧视民事诉讼 → `RB`；`administrative_complaint` 向人社/劳动保障监察反映 → `RC`；`organize_materials` 只整理材料 → `RA` | `civil_consultation` 仅提供起诉权和材料准备信息，不判断法院是否受理或支持 |

### 3.3 终点裁决规则

| 终点 | 权威触发条件 | 行动重点 | 后端文书 |
|---|---|---|---|
| `RA` 证据固定 | 尚无招聘结果、`R4=none`、`R5=no_comparator` 或 `R6=organize_materials` | 保存招聘原文、主体、时间、沟通原话、面试笔记和结果通知 | `evidence_catalog` |
| `RB` 企业/平台沟通或民事咨询 | `R6=request_explanation/platform_complaint/civil_consultation` | 请求说明适用于本人的招聘标准和结果；向平台提交可核验线索；或按第六十二条准备民事咨询材料 | `evidence_catalog` 必选；仅 `R6=platform_complaint` 返回 `recruit_discrimination_complaint`；仅 `R6=request_explanation` 且 `R1=interview/offer_cancelled/rejected_after_application`、用户确有投递或面试经历时返回 `request_rejection_reason`；`civil_consultation` 和纯招聘广告的企业说明路径不返回不匹配函件 |
| `RC` 行政投诉准备 | `R6=administrative_complaint` | 按招聘主体所在地和受理要求整理广告、沟通、不利结果及身份线索 | `recruit_discrimination_complaint`、`evidence_catalog` |
| `OOS` 范围外 | `R5=confirmed_unrelated` | 说明本项目不处理已确认与性别、婚育无关的一般招聘争议 | 不返回文书 |

### 3.4 裁决与措辞约束

- 不得把合法的岗位资格、能力或工作条件差异自动认定为性别歧视；
- 不得承诺企业必须披露其他候选人的信息、评分或录用材料；
- 录音提示限本人参与的对话，并提醒不得窃听、安装设备或传播无关个人信息；
- `RA` 不得写“证据不足所以不存在歧视”，而应给出补证顺序；
- 请求说明函只要求说明适用于用户本人的标准、流程和结果，不索取商业秘密或其他候选人隐私。

## 4. 职场性骚扰及投诉后报复子树

### 4.1 场景目标与安全原则

本树处理违背妇女意愿的言语、文字、图像、肢体等性骚扰，以及利用职权或从属关系实施的骚扰和投诉后报复。安全优先于证据和劳动程序：存在跟踪、威胁、强迫、现实肢体危险或其他紧急风险时，立即进入 `HC`，不得要求用户为了取证继续接触行为人。

用户是否当场明确拒绝不是判断的唯一条件；权力关系、行为内容、持续性、用户表达和客观情境应一并记录。系统不对行为作刑事定性。

### 4.2 完整节点表

| 节点 | 问题 | 技术选项与下一跳 | 标记/法学说明 |
|---|---|---|---|
| `H1` | 对方行为主要是哪一类？ | `verbal_jokes` 言语/黄色玩笑 → `H2`；`text_image_chat` 文字图片或聊天骚扰 → `H2`；`physical_contact` 肢体接触 → `H3`；`quid_pro_quo` 以转正、晋升、考核交换性要求 → `H3`；`stalking_threat` 跟踪威胁 → `H3` | 可多次发生但入口选最主要类型，其他事实写入补充描述 |
| `H2` | 你是否表达过拒绝或不舒服？ | `rejected_but_continues` 明确拒绝后仍继续 → `H4`；`discomfort_ignored` 表达不适后仍继续 → `H4`；`not_expressed` 尚未表达 → `H5` | 未表达不等于同意，也不直接排除性骚扰 |
| `H3` | 现在是否存在紧急人身安全风险？ | `immediate_risk` 存在 → `HC`；`safe_now` 暂时安全 → `H4` | 安全状态应允许用户随时重新评估 |
| `H4` | 行为人身份是谁？ | `supervisor_with_power` 直属上级/有考核权 → `H4A`；`coworker` 普通同事 → `H4A`；`client_partner` 客户/合作方 → `H4A`；`uncertain` 不确定 → `H4A` | 记录其是否掌握考核、排班、续约或资源分配权 |
| `H4A` | 在当前安全状态下，你希望先走哪条路径？ | `preserve_evidence` 先固定证据 → `HA`；`internal_complaint` 向单位投诉 → `H6`；`state_or_police` 向有关国家机关投诉或报案咨询 → `HD`；`civil_consultation` 了解民事诉讼或人格权救济 → `HD` | 标记 `external_state_route` 或 `civil_route`；系统不代替有权机关作受理、行政或刑事定性 |
| `H5` | 你希望先怎么做？ | `preserve_evidence` 先固定证据 → `HA`；`formal_complaint` 正式投诉 → `H6`；`rejection_script` 需要拒绝表达 → `HA` | 拒绝表达必须以安全为前提 |

| `H8` | 已采取哪些行动，公司是否作出不利处理？ | `not_complained` 未投诉 → `HB`；`pending_internal` 内部投诉等待处理 → `HB`；`company_no_action` 公司不处理/包庇 → `HD`；`retaliation` 投诉后出现不利对待 → `H8A`；`external_help` 已向外部求助 → `HD` | `retaliation` 标记来源为 `H8` |
| `H8A` | 投诉后的不利对待达到什么程度？ | `attitude_exclusion` 排挤、冷处理 → `HD`；`material_action` 实际调岗降薪、扣绩效或处分 → `HE`；`exit_pressure` 要求辞职、解除或妨碍工作 → `HE`；`safety_threat` 跟踪、威胁或人身风险 → `HC`；`need_more_info` 暂时无法判断或不符合以上描述 → `HD` | 分别标记 `retaliation_soft`、`retaliation_material`、`retaliation_exit`、`retaliation_threat`、`retaliation_uncertain`；兜底项不得中断路径或自动作实质报复定性 |

### 4.3 终点裁决规则

| 终点 | 权威触发条件 | 行动重点 | 后端文书 |
|---|---|---|---|
| `HA` 固定证据/安全表达 | `H4A=preserve_evidence` 或 `H5=preserve_evidence/rejection_script` | 保存原始信息和时间线；仅在安全时表达拒绝；减少单独接触 | `evidence_catalog` |
| `HB` 内部投诉 | 未投诉、等待处理或准备正式投诉 | 书面提交事实，要求受理、调查、保密、隔离风险和书面告知结果 | `evidence_catalog` 必选；`H8=not_complained` 返回 `harassment_internal_complaint` 且不得返回催办函；`H8=pending_internal` 或已有可核验投诉记录时只返回 `request_company_investigation`，不重复生成首次投诉说明 |
| `HC` 安全优先 | `H3=immediate_risk` 或 `H8A=safety_threat` | 离开危险环境、联系可信任人员和当地紧急求助渠道；仅在安全时留存材料 | `emergency_help_record`、`evidence_catalog` |
| `HD` 外部求助/轻度或未分级报复 | `H4A=state_or_police/civil_consultation`，或公司不处理、已外部求助、`H8A=attitude_exclusion/need_more_info` | 区分单位主管部门、公安报案、人格权民事咨询和伴随劳动权益争议；固定投诉与后续变化 | 默认 `evidence_catalog`；存在 `{node:H4A, flag:civil_route}` 时附 `personality_rights_civil_materials`；只有同时存在属于人社监督或劳动争议的具体事项时，才附 `labor_inspection_materials` |
| `HE` 实质报复 | `H8A=material_action/exit_pressure` | 固定投诉、知悉投诉人员、不利措施、时间关联及实际损失；区分人格权救济与劳动争议请求 | 默认 `request_company_investigation`、`evidence_catalog`；仅 `H8A=material_action` 且存在可量化调岗、降薪、绩效或处分劳动请求时附 `arbitration_application_points`；`exit_pressure` 不生成解除、辞职效力、赔偿或仲裁文书 |

### 4.4 裁决与措辞约束

- 不要求用户与行为人对质、继续单独接触或冒险获取证据；
- 不因用户没有明确拒绝、没有录音或没有证人就否定其陈述；
- 不使用“肯定构成性骚扰”“一定能追责”或刑事罪名；
- 内部投诉文书使用“反映”“请调查核实”等措辞，并要求保护隐私和个人信息；
- `retaliation_exit` 只处理投诉后报复关联，不扩展为普通违法解除咨询；
- `HC` 的结果先展示安全行动，再展示文书和一般法律信息。

### 4.5 条件标记

本树使用 `evidence_weak`、`external_state_route`、`civil_route`、`retaliation`、`retaliation_soft`、`retaliation_material`、`retaliation_exit`、`retaliation_threat` 和 `retaliation_uncertain`。后端只信任路径重放生成的带来源 `canonicalFlags`，不得接受客户端自行提交的标记。

## 5. 同工同酬/晋升受限子树

### 5.1 场景目标

先判断差异属于薪酬福利还是职业发展，再核对可比较对象、工作可比性、可能的客观差异、性别或婚育关联和证据状态。系统只提供事实整理、书面询问、申诉及投诉/仲裁准备，不替代仲裁机构或法院作个案认定。

## 6. 产假/哺乳时间与待遇争议子树

### 6.1 场景目标

区分国家法定产假、地方延长生育假、哺乳时间、产假期间工资、生育津贴、参保和生育医疗费用问题。国家规则可以直接匹配；地方假期天数、津贴范围、申领流程和补差规则必须按实际工作地、参保地及事件发生时间加载，不能全国统一回答。

“哺乳假”容易与国家规定的每日哺乳时间混淆。界面应优先使用“每天哺乳时间”；用户主张连续数日或数月的“哺乳假”时，必须进入地方规则核验。

| `LB` 投诉/仲裁准备 | 内部沟通无果或已行政投诉 | 按具体问题准备人社、医保经办、劳动保障监察或仲裁材料 | 默认 `evidence_catalog`；符合监察职责时附 `labor_inspection_materials`；存在可仲裁的工资、待遇或劳动权利请求时附 `arbitration_application_points` |
| `LC` 单位争议时效核验 | 单位责任路径（含 `L3B=employer_nonpayment_or_no_insurance`）、`L4=over_one_year` 且尚未仲裁 | 核对一般仲裁时效、劳动报酬特别规则和主张记录；不得用于社保/医保经办机构核定或支付争议 | `legal_aid_questions`、`evidence_catalog` |
| `LD` 已仲裁 | `L6=arbitration_started` | 对照仲裁请求补齐假期、工资、参保、津贴及送达证据 | `arbitration_supplement_list`、`evidence_catalog` |

### 6.4 地方规则强制约束

存在 `{node:L0, flag:region_uncertain}` 或 `{node:L0, flag:region_partly_confirmed}` 时，涉及地方延长假、生育津贴、医保结算或地方补差规则的路径必须先提示补充实际工作地、参保地和事件发生日期。信息补齐前，后端只能返回全国性规则和“需核对地方规则”的占位说明，不得返回具体地方天数、金额、比例或申办期限；该限制在 `L2`、`L3A/L3B` 和裁决包组装时均须复核。

以下情形只有在 `workRegion/insuranceRegion + eventDate` 均明确、且地方规则记录为 `published` 时，裁决包才能展示具体地方天数、金额或申领机关：

- 地方延长产假、奖励假、育儿假或连续“哺乳假”；
- 延长假期间待遇承担主体；
- 生育津贴申领条件、发放路径、计发天数和差额处理；
- 生育保险与职工医保合并实施后的本地经办流程；
- 地方增加的流产假、难产假、多胞胎假及其他待遇。

缺少地方规则时，后端仍可返回国家法依据和材料核对步骤，但必须显示：

> 您所在地区的延长假期和生育津贴细则尚需按实际工作地、参保地及事件发生时间核对。本结果暂不提供具体地方天数或金额。

## 7. 文书模板交付

### 7.1 共用规则

- 以下均为法学自然语言稿，开发按编制手册 10.8 转为 JSON；
- `{{字段}}` 为结构化文书字段；
- `[条件：...]` 控制下一完整段落；
- `[字段条件：fieldName 已填写]` 控制下一完整段落；字段为空时整段省略，不触发 `MISSING_DOCUMENT_FIELDS`；多个字段以“均已填写”连接时必须全部有值，以“任一已填写”连接时至少一个有值即可渲染；
- 同一段落前连续出现 `[条件：...]` 与 `[字段条件：...]` 时，两者按逻辑“且”合并，节点条件和字段条件均满足才渲染；
- `[引用核对：...]` 只供开发核对法律依据映射，不进入成文；
- 事实不明时删除对应条件段落，不得由模型补写；
- 选填字段一旦被命中的条件段落引用，即转为该段的 `requiredFieldsWhenRendered`；缺失时后端返回 `MISSING_DOCUMENT_FIELDS` 让前端补充，不能输出带空白占位符的半成品；
- 任何模板使用前均显示“请逐项核对事实、金额、日期和收件主体，并保留发送及送达记录”。

下列元数据默认适用于 7.2-7.15 的每一份模板，开发转换时必须展开写入每份 JSON，不得依赖文档的隐式继承：

| 字段 | 默认值/规则 |
|---|---|
| `title` | 对应小节标题中的文书名称 |
| `version` | `1.2.0-draft` |
| `conditionIndexVersion` | `1.3.0` |
| `warnings` | 至少包含“使用前逐项核对事实与字段”“保留发送和送达记录”；清单类文书还须注明“不是成品申请书” |
| `status` | `draft`；未完成渲染快照法学复核不得发布 |
| `legalBasisKeys` | 禁止配置；裁决包法律依据区完全由第 8-9 章的依据库与终点映射控制 |

对应条件段命中后，段内占位符自动纳入 `conditionalRequiredFields`；未命中时不收集。正文自然语言可以出现法规名称和条款号，但 `[引用核对：legalBasisKey]` 仅用于开发与法学交接核对，不作为渲染或法条展示控制逻辑。

| `HE` | `women_rights_25`、`women_rights_72` | `women_rights_84`、`civil_code_1010`、`women_rights_74`、`labor_dispute_arbitration_27` | 报复关联经核对时展示第84条；仅 `H8A=material_action` 且存在可仲裁的具体工资、绩效或处分请求时展示第27条；`exit_pressure` 不展示解除实体条款或自动进入仲裁路径；行政监督条件同理受限 | 把性骚扰侵权请求与劳动仲裁请求混为一体，或扩展为普通违法解除服务 |

`H8A` 的报复标记用于控制事实说明和劳动程序材料，不单独作为“报复必然违法”的自动定性规则。法学审核须结合不利措施内容、决定主体、时间关联和适用程序确认裁决包措辞。

`women_rights_77` 在性骚扰树同样不自动映射。只有法学负责人完成公共利益条件专项复核，确认相关单位未采取合理预防和制止措施并可能导致社会公共利益受损时，才能作为 `requiresLegalReview: true` 的折叠依据返回。

## 10. 法学审核用例

以下用例是法学验收的最低集合，不替代技术方案要求的全路径测试。每个用例均须核对：终点、文书白名单、条件段落、必选/条件法条、禁止性表达和 OOS 边界。

### 10.1 孕产期调岗降薪树

| 用例 | 答案要点 | 预期终点 | 必审问题 |
|---|---|---|---|
| P-01 | 在职；书面降薪；孕期；工资已经降低；未签；有流水；未行动 | `PA` | 异议函出现书面通知、孕期、降薪段，可附恢复待遇函；展示第5条和第48条 |
| P-02 | 在职；口头调岗；哺乳期；岗位已经变化且条件变差；仅口头沟通 | `PA` | `P6=transfer_only` 本身表示已实施；应出现请求书面确认段，不得写调岗当然无效 |
| P-03 | 已暗示明确将调岗降薪；`P4=not_started` | `PE` | 产生 `anticipated_action`；跳过 `P5-P7`，只返回证据目录，不渲染已实施、恢复待遇或差额段 |
| P-04 | 只有态度变化，无具体安排 | `PE` | 只返回证据目录；不得生成恢复岗位请求或认定歧视 |
| P-05 | 已签协商文件但称受压；有聊天；未正式行动 | `PB` | 所有路径经过 `P9/P10`；文书出现签署背景核实段，不得断言文件无效 |
| P-06 | 主动提交过辞职；公司要求离开且孕产关联不确定；有孕产时间线 | `PF` | 只处理孕产关联和材料核对，不生成辞职效力、解除赔偿或调岗降薪文书 |
| P-07 | 明确超过一年，但期间曾书面主张 | `PC` | 完整展示时效中断规则，不写“不能仲裁” |
| P-08 | 公司曾要求主动辞职，用户已经申请仲裁 | `PD` | `arbitration_started` 必须优先于 `PF`；只返回补充材料和证据目录，不重复生成申请要点 |
| P-09 | 孕期调岗已执行并增加不适宜劳动；有医疗证明线索；未行动 | `PA` | 条件展示第47条、第6条；不由系统判断医学适宜性 |
| P-10 | 用户明确确认解除与性别婚育孕产无关 | `OOS` | 不返回文书和本项目实体法条，显示范围外说明 |
| P-11 | 书面仅调岗；已执行；工资未变；岗位被边缘化；已书面投诉 | `PB` | 不展示第5条的“不得降低工资”作为当前已发事实；可按职业发展受限条件展示第48条 |
| P-12 | 口头调岗并降薪；哺乳期；已执行且工资下降；已外部投诉 | `PB` | 展示第5/48/83条的条件必须由实际降薪和行政路径命中 |
| P-13 | 已离职但孕产关联不确定；一年内；有时间线；未行动 | `PF` | 显示 `relation_uncertain` 补事实提示，只返回证据目录，不返回法援问题、时效或仲裁文书 |
| P-14 | 收到孕产关联解除通知、选择超过一年，但已经申请仲裁 | `PD` | 已仲裁同时优先于 `PF` 和 `time_risk`，不得错误跳到 `PF/PC` |
| P-15 | 明确暗示将降薪；`P4=not_started` | `PE` | 不继续询问孕产阶段和实际影响；只固定原话、时间和现待遇 |
| P-16 | 书面调岗；产假中；已执行但影响不明显；未签文件；未行动 | `PA` | `harm_low` 不得被表达为“没有损害”或“单位可以调岗” |
| P-17 | 口头通知后无法判断实际行为是否与孕产有关；暂无签署信息；只口头沟通 | `PA` | `P6=relation_uncertain` 直接进入 `P9`，路径不应强制经过 `P8`；结果提示补充关联证据 |
| P-18 | 因孕产不利措施已离职；一年内；已内部投诉 | `PF` | 仅输出证据目录，不生成法援问题、普通违法解除或调岗降薪文书 |
| P-19 | 因孕产收到口头辞退；时效不确定；证据弱；未行动 | `PF` | 保留 `time_uncertain/evidence_weak`，只返回证据目录，不在事实未明时认定解除违法 |
| P-20 | 仅态度变化，没有具体调岗降薪暗示 | `PE` | 只给固定证据和确认式记录，不展示第5/48条的已发违法结论 |
